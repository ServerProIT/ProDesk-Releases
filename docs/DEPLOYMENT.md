# Развёртывание ProDesk

## Установка одной командой

Откройте **64-разрядный PowerShell от имени администратора** на клиентском
компьютере и выполните:

```powershell
& { $p = Join-Path $env:TEMP ('ProDesk-' + [guid]::NewGuid().ToString('N') + '.ps1'); Invoke-WebRequest -UseBasicParsing 'https://github.com/ServerProIT/ProDesk-Releases/releases/latest/download/Deploy-ProDesk.ps1' -OutFile $p; & powershell.exe -NoProfile -ExecutionPolicy Bypass -File $p }
```

Команда работает после публикации первого релиза в публичном
[ProDesk-Releases](https://github.com/ServerProIT/ProDesk-Releases/releases).
Авторизация GitHub на клиентском компьютере не нужна.

Скрипт скачивает последнюю стабильную версию, проверяет SHA256 и метаданные
ProDesk, устанавливает приложение в `C:\Program Files\ProDesk`, включает
автоматический запуск службы `ProDesk` и добавляет ярлык приложения в автозагрузку
всех пользователей. Повторный запуск не переустанавливает ту же версию, но
восстанавливает службу, автозапуск и задачу обновления.

Первая сборка с версией `1.5.0` переводится на нумерацию ProDesk `0.1.0`.
Другие понижения версии не выполняются.

## Автообновления

При каждом запуске установленного приложения или значка в трее запускается
задача `ProDesk Update`. Также она проверяет обновления через минуту после
загрузки Windows. Задача работает от SYSTEM: после первой установки запросы UAC
для обновлений не нужны. Обычные пользователи могут только запускать задачу;
изменять её команду, скрипт и скачанные пакеты могут администраторы и SYSTEM.

Сначала скачивается и проверяется пакет. При сетевой ошибке работающая версия
остаётся доступной; следующая проверка выполняется при следующем запуске.
Во время установки обновления ProDesk и активные удалённые сеансы могут быть
перезапущены. Установленная версия и запущенная служба проверяются после
обновления; при ошибке выполняется попытка возврата к предыдущей копии.
Если возврат также не удался, резервная копия сохраняется для восстановления.

Журнал: `C:\Program Files\ProDeskMaintenance\update.log`.

Принудительная проверка из PowerShell:

```powershell
schtasks.exe /Run /TN 'ProDesk Update'
```

В переносимом режиме автообновление не настраивается: сначала установите
приложение через интерфейс или командой выше. Автоматическое развёртывание
рассчитано на стандартный путь установки. Старые программы без нового механизма
обновления необходимо один раз обновить этой командой.

При удалении программы оставшаяся задача не устанавливает её заново. При
необходимости задачу можно удалить из административного PowerShell:

```powershell
Unregister-ScheduledTask -TaskName 'ProDesk Update' -Confirm:$false
```

## SmartScreen

Версия публикуется без Authenticode-подписи по решению владельца проекта.
Предупреждение SmartScreen при ручном скачивании EXE может сохраняться.
Скрипт проверяет пакет перед снятием метки скачанного файла и не меняет
глобальные параметры Defender или SmartScreen. SHA256 защищает от повреждения
пакета; доверие к издателю опирается на HTTPS и доступ к GitHub-репозиторию.

## Выпуск следующих версий

Измените версии в `Cargo.toml`, `Cargo.lock`, `libs/portable/Cargo.toml` и
`flutter/pubspec.yaml`. CI получает тег и имена файлов из `Cargo.toml`.
Исходники, EXE, ZIP для развёртывания, установочный скрипт, лицензия и SHA256
публикуются в приватном ProDesk и публичном ProDesk-Releases.
Для публикации в другой репозиторий нужен секрет `PRODESK_RELEASES_TOKEN`
в репозитории исходников с правом записи содержимого ProDesk-Releases.

Релиз с уже опубликованным номером не следует перезаписывать: выпустите
следующий номер, чтобы клиенты могли обнаружить обновление.
